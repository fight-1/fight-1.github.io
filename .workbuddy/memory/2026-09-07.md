## 学习任务：分析 fight-1 项目
- 类型：Astro + Tailwind 个人主页（"Tri-State Self" 概念），纯客户端、无后端。
- 核心机制：三套主题 Mirror / Version / Loop，15s 自动循环、按 T 切换、按时间/空闲选默认、可配色自定义（localStorage 持久化）。
- 数据层：客户端直连 GitHub REST API，5 分钟浏览器缓存，失败回退假数据；Hero/Stats/Battle Log 用真实数据，部分文案（skills/patchNotes/projects）为 index.astro 内联静态数据。
- 部署：GitHub Actions 两 workflow —— deploy.yml（构建并部署 Pages）、metrics.yml（lowlighter/metrics 每周生成 SVG，需 METRICS_TOKEN secret）。
- 组件：index.astro（主页面）、ParticleBackground（Canvas 粒子+彩蛋）、ThemeIndicator（主题点+配色面板）、GitHubData（内联 SVG 图表）。
- 重要代码观察：
  1. `src/lib/github-api.ts`、`src/lib/charts.ts`、`src/lib/github-data-client.ts`、`src/scripts/theme-switcher.ts` 均**未被任何 .astro 组件 import**（逻辑已内联进 index.astro / GitHubData.astro 的 client 脚本），属孤儿代码/重复实现，构建不打包。
  2. `three` 依赖在 package.json 声明但无任何 import（粒子用原生 Canvas 2D），属未使用依赖。
  3. 彩蛋：连点 8 次=CHAOS MODE；输入 "fight"=火焰模式；空闲 60s=文字聚拢 "fight-1"。
- 本地运行：`npm install` → `npm run dev`；构建 `npm run build` → dist/。
